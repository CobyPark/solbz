Claude 12. 재현되는 버그부터 코드 수정 맡기기

솔루션 비제트 · Anthropic 공식 문서 참고 가이드 · 2026.10.28

“검색창에 A를 넣고 Enter를 누르면 결과가 비지만 검색 버튼을 누르면 나온다”처럼 실패하는 순서를 적어 보세요. 검색이 안 된다는 설명에 재현 조건이 붙으면 Claude Code가 수정 후 다시 시험할 지점도 뚜렷해집니다.

오류가 나는 순서를 적는다

현재 브랜치와 커밋하지 않은 변경을 확인하고 시작합니다. 이미 수정 중인 파일이 있다면 그 목적도 알려 주세요. 재현 정보에는 화면 또는 명령, 입력값, 실제 결과, 기대 결과가 들어가면 됩니다. 로그 전체보다 오류와 직접 관련된 부분을 골라 주는 편이 읽기 쉽습니다.

검색 화면에서 입력칸을 비운 채 조회하면 오류가 발생해.
기대 결과는 오류 없이 빈 검색어 안내를 보여 주는 것이야.
일반 검색과 기존 API 응답 형식은 유지해 줘.
먼저 관련 코드를 찾고 원인을 설명한 뒤 필요한 부분을 수정해 줘.
빈 입력과 일반 입력을 검증하고 실행한 명령과 결과를 알려 줘.
커밋과 푸시는 아직 하지 말아 줘.

원인 설명에 나온 파일과 실제 변경 파일이 이어지는지 봅니다. 단순 입력 오류를 고치면서 인증이나 데이터 형식까지 바뀌었다면 왜 필요한지 검토해야 합니다. 수정 범위를 줄이되 같은 원인에서 생기는 오류까지 놓치지 않도록 관련 호출부를 함께 살펴봅니다.

권한 요청은 실행할 일을 읽는 기회

Claude Code의 동작은 권한 모드와 허용 규칙의 영향을 받습니다. 명령 실행이나 파일 변경을 요청받으면 대상과 이유를 읽으세요. 계획을 세워 달라는 요청과 실제 편집·배포까지 맡기는 요청은 범위가 다릅니다. 작업 지침에 적었다는 이유만으로 실행 권한이 설정되는 것도 아닙니다.

통과했다고 적힌 검사만 보지 않기

테스트가 통과했더라도 빈 입력을 실제로 다루는 검사인지 봅니다. 실행하지 못한 검사는 통과한 검사와 따로 남겨야 합니다. 화면 문제라면 브라우저에서 오류 문구와 입력 유지 여부를 직접 볼 필요도 있습니다.

마지막에는 git diff로 요청과 관계없는 수정이 섞였는지 읽습니다. 테스트를 위해 만든 임시 자료나 로그가 전달 파일에 포함되지 않았는지도 봅니다. 검토할 기준은 최종 요약의 자신감보다 재현 조건, 변경된 코드, 실행 결과가 서로 맞는지입니다.

수정 후에는 처음 실패했던 입력을 다시 넣습니다. 버튼과 Enter 입력이 모두 되는지, 검색 결과가 없을 때 화면은 어떤지도 이어서 보세요. 한 경로를 고치면서 다른 경로를 깨뜨리지 않았는지 확인할 수 있습니다.
