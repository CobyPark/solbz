Claude 11. CLAUDE.md에 어떤 규칙을 적을까

솔루션 비제트 · Anthropic 공식 문서 참고 가이드 · 2026.10.28

테스트 명령을 매번 설명하거나 수정할 폴더를 자꾸 잘못 짚는다면 CLAUDE.md에 적어 둘 내용이 있습니다. 이 저장소에서 쓰는 실행 명령, 파일 위치, 편집할 때 주의할 부분부터 남겨 보세요.

코드에서 알기 어려운 이유를 적는다

폴더 이름만으로 알 수 없는 운영 사정이나 팀에서 정한 배포 조건을 적어 보세요. 예를 들어 고객에게 전달한 파일명이라 바꾸면 안 되는 경우, 생성 파일 대신 원본을 수정해야 하는 경우가 있습니다. 이유까지 한 줄 덧붙이면 예외 상황에서도 판단하기 쉽습니다.

# 사이트 작업 메모

- docs/generated/는 생성 결과물이다. 수정은 원본 템플릿에서 한다.
- 다운로드 파일명은 기존 고객 안내와 연결돼 있으므로 변경하지 않는다.
- 문의 양식을 바꾼 경우 빈 입력과 정상 입력을 각각 확인한다.
- 테스트를 실행하지 못했다면 이유를 완료 보고에 적는다.

위 경로와 규칙은 설명용입니다. 자신의 저장소에 없는 폴더나 검사 명령을 그대로 복사하지 마세요. 처음에는 실제로 자주 놓치는 조건 서너 개로 시작하고, 작업하면서 불필요한 규칙을 줄여도 됩니다.

자동 메모리와 직접 쓰는 지침

공식 문서는 사용자가 작성하는 지침 파일과 Claude가 작업 중 남기는 자동 메모리를 구별합니다. 직접 관리할 운영 규칙은 지침에 적고, 자동으로 남은 내용도 가끔 읽어 오래된 판단이 있는지 살펴보세요. 둘 다 대화 맥락을 돕는 자료이며 접근 제어 설정을 대신하지는 않습니다.

사용자 전체에 적용할 규칙과 이번 저장소에만 필요한 규칙도 나눕니다. 특정 프로젝트의 파일명 제한을 전역 지침에 넣으면 다른 저장소에서도 불필요한 제약이 될 수 있습니다. 하위 폴더에 별도 지침이 있다면 어느 범위에서 읽히는지도 공식 탐색 규칙과 대조합니다.

지침을 고친 날에는 작은 요청으로 읽어 보기

“현재 작업에 적용되는 지침 파일과 관련 규칙을 알려 줘”라고 요청한 뒤 실제 경로와 설명을 봅니다. 파일명이 틀렸거나 다른 폴더에서 실행했다면 내용을 아무리 강조해도 원하는 지침을 읽지 못할 수 있습니다.

규칙을 추가한 뒤에는 실제 작업 하나를 맡겨 보세요. 적어 둔 테스트를 실행하는지, 파일 위치를 제대로 찾는지 보면 지침이 도움이 되는지 알 수 있습니다. 행동이 달라지지 않는 긴 문장은 구체적인 경로나 명령으로 고쳐 볼 만합니다.
